# Совместная работа над проектом

## Прочитать перед любой задачей

1. `docs/ARCHITECTURE.md` — куда класть код, что обязано быть в ядре,
   бюджеты производительности, что проверить перед слиянием.
2. `docs/DESIGN.md` — какую игру делаем и фильтр для новых фич.
3. Этот файл — как работать с git.

Перед слиянием в `master` запустите `.\tools\check.ps1` и сливайте только при
«ВСЁ ЗЕЛЁНОЕ». В отчёте пользователю укажите результат проверки.

## Git и ветки

В проекте одновременно работают несколько моделей. По указанию пользователя
каждая новая задача выполняется в отдельной ветке, а после завершения и проверки
сливается в общую ветку. Общая ветка на момент договорённости — `master`.

- Для задачи создавайте отдельную ветку с понятным именем и отдельный
  `git worktree`. Не переключайте ветку в общей рабочей папке: другой агент
  может продолжать работу в ней.
- Перед началом проверьте состояние Git и актуальные инструкции. Не включайте
  чужие незакоммиченные изменения в свой коммит и не сбрасывайте их.
- Делайте изменения и подходящие проверки в рабочей папке своей задачи.
- После завершения коммитьте только изменения задачи и сливайте её ветку
  в общую. Пользователь уже разрешил такое слияние для завершённых задач.
- Перед слиянием повторно проверьте состояние общей ветки и рабочей папки.
  Сохраните чужую работу; не используйте принудительный сброс, переключение
  или автоматический stash чужих изменений. При конфликте намерений согласуйте
  его с пользователем, не выбирайте одну из версий вслепую.
- После слияния выполните необходимые проверки интеграции и сообщите результат.
  Разрешение на слияние не означает разрешения на публикацию или push.
