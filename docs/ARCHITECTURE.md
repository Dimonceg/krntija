# Архитектура Krntija — правила для всех

Читают все модели перед любой задачей. Правило мешает — не обходите молча,
напишите в отчёте пользователю; архитектор поправит документ. Роли и git —
`AGENTS.md`; команды и грабли — `docs/HANDOFF.md`; модели — `docs/ART.md`.

## 1. Слои

```
core/Krntija.Core       правила: числа, состояния, решения. Без Godot.
core/Krntija.Core.Tests тест на каждое правило.
game/scripts            показ и ввод: сцена, физика, звук, UI. Правил не придумывает.
game/assets             модели, текстуры, звук (docs/ART.md).
tools                   сборка, проверки, генераторы моделей.
```

**Главное правило.** Число, влияющее на игру (цена, урон, расход, шанс, вес,
награда, время), живёт в `core` и покрыто тестом. Сцена спрашивает ядро «можно
ли?» и «что вышло?» и только показывает. Причины: баланс без запуска игры, в
коопе правила выполняет хост, баг ловится тестом за миллисекунды.

```csharp
// core: решение и причина
public static ActionResult TryRepairAtWorkbench(GameSession session, out Part? repaired)
// game: только показ
switch (WorldActions.TryRepairAtWorkbench(_car.Session, out var part)) { case ActionResult.NotEnoughMoney: … }
```

Неправильно: `if (session.Wallet.Money < 25) …` в `Main`.

- «Что и где стоит в мире» решает ядро (`WorldGen`, ADR 0002); сцена строит по плану.
- Валюта — доллары; формат цены только `Money.Format(…)`, `$` руками не писать.
- Строки для игрока — в сцене, числа в них — из констант ядра.

## 2. Состояние

- Всё, что игрок может изменить в мире (лут, шлагбаумы, места, завалы, детали
  машины), — состояние в ядре (`GameSession`), попадает в `SaveData`, с тестом
  «сохранил → загрузил → то же».
- Стабильный id, не зависящий от порядка узлов: `"<что>:<источник>:<номер>"`,
  номер — из генератора по сиду. Конструкторы — `WorldState` (`WorldState.Loot("house", 3)`),
  отметка — `MarkWorld(id)`, показ после загрузки — `SyncWorldState()`. Новый
  источник — новое имя, а не чужая нумерация.
- `SaveData` — по ADR 0002, п. 6: новая версия читает старую через значения по
  умолчанию; на каждую версию образец `core/Krntija.Core.Tests/Saves/save_vN.json`
  и тест загрузки.
- Генерация детерминирована по сиду (`Pcg32`); никаких `GD.Randi()`/`Random`.

## 3. Сцена (`game/scripts`)

- `Main` — partial по темам (`Main.<Тема>.cs`, таблица в `HANDOFF.md`).
  **В `Main.cs` новых методов не добавлять.** `Main` — сборка сцены и маршрутизация
  ввода; окна (`Hud`, `BackpackUi`, `MapUi`) сами читают сессию.
- Файл > ~600 строк — повод делить, > 1000 — обязательно.
- Штука со своим циклом (`Car`, `Hud`, `CarAssemblyVisual`) — свой `Node`.
- Генераторы в сцене (`WorldScatter`, `ChunkBuilder`) — «построй по плану и верни
  данные»; взаимодействия не регистрируют сами, их регистрирует `Main`.
- Имена по смыслу: никаких `Foo2`, `NewFoo`.

**Мир кусками.** Содержимое куска — дети `Chunk_{k}` в локальных координатах.
Всё, что `Main` держит про кусок, помечено номером и снимается в `OnChunkUnloading`.
Сцена у нуля, настоящая позиция = сцена + `WorldOrigin`; поле с позицией сцены в
`Main` — добавить в `ShiftScene`. Шейдер с шумом от мировой позиции объявляет
`global uniform vec3 world_origin;`.

**Клавиша E.** Цель выбирает только `Main.SelectTarget()`; действие и подсказка
берут её оттуда. Правило выбора — ядро, `TargetSelector`; новая точка — строка в
`Rules()`. Цель за стеной не выбирается (`Candidate.InSight`, луч в
`Main.InteractionSight.cs`); точке с моделью — `Visual`, чтобы её коллизия не
закрывала её саму и чтобы работала обводка (`InteractionHighlight`). Обводимое
должно иметь свои меши: неподвижные — в `StaticBatcher.SkipGroup`.

**Машина из деталей** (ADR 0003). Кузов — `CarAssemblyVisual` по узлам
`Socket_`/`Open_` из GLB; состояние берёт из ядра (`ICarAssemblyState`).
Гнёзда — `Car.SocketGlobal(id)`, id — `PartSlotIds`. Навесы — `CarUpgradeVisuals`.

**Esc.** Ловит `MenuUi` → `Main.OnEscape`: сначала `CloseGameWindows`, потом
пауза. Новое окно поверх игры — добавить в `CloseGameWindows`.

**Падения при выходе (0xC0000005).**
- Результаты `IntersectRay`/`IntersectShape` — только через `PhysicsHit.Collider<T>()`
  и `PhysicsHit.Position()`.
- Проверки выходят через `QuitSoon(код)`, не `GetTree().Quit()`.
- Ресурс Godot в статическом поле — только с освобождением в `StaticCaches.Release()`.
- Созданные в C# `InputEvent` и подобные обёртки — `using`.
- Не вызывать `GetScript()` в циклах; «наш» узел — `node.GetType().Assembly == typeof(Main).Assembly`.

## 4. Производительность (GTX 1060 6 GB)

Мерить **в 1920×1080**: `godot --resolution 1920x1080 --path game -- --perf`.
Смотреть `кадров отрисовки` (кадр, процессор, видеокарта) и `рывки`.
Сравнивать с `master` в тот же день, по 2–3 прогона (разброс до 5 %).

- `--perf-seconds=60` — минута езды с подгрузкой кусков;
- `--perf-off=shadows,ssao,glow,fog,multimesh` — цена одного вида нагрузки;
- `--perf-spikes` — долгие кадры и события кусков;
- `--perf-car [--open=all]` — машина крупно: вызовы отрисовки, память текстур;
- `--shot … --perf-off=… --shot-name=…` — снимок для сравнения картинки;
- `--check-scene` — разбор сцены, `--no-batch` — без слияния мешей.

Опора на 2026-10-26: ~4,6 мс на кадр (видеокарта 4,0), ~290 МБ видеопамяти,
~720 узлов, ~150–220 вызовов отрисовки. Упираемся в видеокарту. При 1080p:
SSAO 0,55 мс, тени 0,43, туман 0,39, растительность 0,33; свечение выключено.

| Метрика | Бюджет | Если превысили |
|---|---|---|
| Кадр в `--perf` | ≤ 8 мс | найти добавленное, упростить |
| Видеопамять | ≤ 2 ГБ | сжать и общие текстуры, атлас |
| Постройка куска | ≤ 4 мс в кадр | очередь на несколько кадров |
| Вызовы отрисовки | ≤ 1500 | MultiMesh, слияние статики |
| Узлы | ≤ 5000 | не узел на каждый ящик |
| Треугольники на модель | `docs/ART.md` | LOD, упростить |

- Повторяющееся — `MultiMeshInstance3D`.
- Статика сливается `StaticBatcher` (пропускает узлы со скриптом). Что код потом
  удаляет, двигает или перекрашивает — в `StaticBatcher.SkipGroup`; меняющийся
  материал — в `keepInstance`.
- Материалы переиспользовать; текстуры — общими файлами, не копией в каждом GLB.
- В `_Process` ничего тяжёлого (поиск по всем точкам, `GetNode`, аллокации) —
  дорогое по таймеру.
- Мир, которого игрок не видит, не должен стоить кадров.
- Изменение цифр больше 10 % — «до/после» в описании коммита.

## 5. Ассеты

`docs/ART.md`: GLB, метры, +Y вверх, лицо по −Z, центр на земле; подмена через
`ModelLibrary`/`PropFactory` без правок логики; коллизия простыми формами.
Новая модель места проходит `--check-props`.

## 6. Проверки

`.\tools\check.ps1` перед каждым слиянием (`AGENTS.md`). Красное не от вашей
задачи — не чинить вслепую, написать пользователю. Красный `master` на стыке
веток чинит тот, кто слил вторым.

- Правило в ядре → тест в `core/Krntija.Core.Tests`.
- Механика в сцене, проверяемая без рук → своя `--check-*`/`--selftest-*`
  (файл `Main.<Тема>Check.cs`) + строка в `check.ps1`. С окном проверка может
  сохранять снимки через `Snap`.
- «С тестами» в описании коммита — только если тесты в коммите.

## 7. Файлы и кодировки

- `.cs`, `.md`, `.gd`, `.py` — UTF-8 **без** BOM.
- `.ps1` с кириллицей — UTF-8 **с** BOM (PowerShell 5.1 иначе ломается). Инструменты
  правки снимают BOM — первый шаг `check.ps1` это ловит; если BOM потерял сам
  `check.ps1`, он не запустится (ошибки разбора в первой строке).
- `Set-Content`/`Out-File` — только с `-Encoding`.
- `.uid` — вместе со скриптом; `.import` — с LF (`.gitattributes`).
- Снимки для документации — `docs/screenshots/`, один-два на задачу.
