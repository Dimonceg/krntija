# ADR 0002 — Бесконечная дорога и генерация мира в ядре

- **Дата:** 2026-10-25
- **Статус:** принято
- **Реализация:** фаза 1 — модель фич, фаза 2 — архитектор, фаза 3 — модель фич

## Контекст

Игра — бесконечная песочница (`docs/DESIGN.md`). Сейчас мир — фиксированные
2,5 км (`RoadPlanner.Generate(totalMeters: 2500)`) с тупиками на концах, а план
мира (что и где стоит) живёт в сцене: `RoadsideMap`, `BackcountryMap`, `MapLife`.
Из-за этого:

- дальше 2,5 км ехать некуда — нет главной оси прогресса «дальность»;
- план мира нельзя проверить тестом и нельзя гарантировать одинаковым в коопе;
- id лута зависят от порядка циклов в сцене: правка одного генератора сдвигает
  номера у других и «переносит» состояние в сейве.

## Решение

### 1. Дорога — функция от станции, а не накопленный поворот

Вводим **станцию** `s` — метры вдоль общего направления дороги (ось +S мира;
в Godot это −Z). Дорога в любой точке вычисляется сразу, без соседей:

```
RoadCurve.Lateral(s)  — отклонение вбок, м (плавный шум по сиду)
RoadCurve.Height(s)   — высота, м (как RoadProfile.HeightAt)
RoadCurve.Point(s)    — (x = Lateral(s), y = Height(s), s)
RoadCurve.Heading(s)  — направление из производной Lateral
```

Почему не кривизна, как сейчас: положение при заданной кривизне — интеграл всех
поворотов до этой точки. Чтобы построить кусок №500, пришлось бы пройти 499
предыдущих; после загрузки сейва и у второго игрока в коопе это долго.
Функция от `s` даёт случайный доступ за O(1).

Цена решения: дорога не делает петель и не разворачивается назад. Для дороги
«всё дальше от дома» это нормально.

Ограничения (проверяются тестами на 100 км):

- `|dLateral/ds| ≤ tan(55°)` — дорога не идёт поперёк своей оси;
- радиус поворота ≥ 60 м (вторая производная ограничена);
- уклон ≤ 8 % (как сейчас `RoadProfile.MaxSlope`).

Длина пути по дороге ≠ `s` (на поворотах длиннее). Одометр считает путь
машины; `s` — только адрес в мире.

### 2. Куски

Мир делится на **куски** фиксированной длины по станции:
`ChunkLength = 256 м`, кусок `k` покрывает `s ∈ [k·256, (k+1)·256)`.
Кусок 0 — старт (дом игрока). Отрицательные куски не генерируются: за домом
тупик (как сейчас отбойник «Начало»).

```csharp
// core/Krntija.Core/WorldGen/
public static class WorldGenerator
{
    public static ChunkPlan Plan(ulong worldSeed, int chunkIndex);
}

public sealed record ChunkPlan(
    int Index,
    double StartS, double EndS,
    int Tier,                          // опасность и ценность, растёт с расстоянием
    IReadOnlyList<PlacePlan> Places);

public sealed record PlacePlan(
    string Id,                         // "c12/p3"
    PlaceKind Kind,                    // GasStation, Village, Ruins, Farm, Checkpoint, House, Barn, Well, ...
    double S, double Lateral,          // где: станция и смещение от оси дороги (знак — сторона)
    double Yaw,                        // поворот постройки, рад
    int VariantSeed,                   // для выбора модели/варианта в сцене
    IReadOnlyList<LootPlan> Loot,
    IReadOnlyList<UsePlan> Uses);      // колонка, лавка, кровать, колодец, скупщик…

public sealed record LootPlan(string Id, string ItemId, int Count,
    double OffsetX, double OffsetY, double OffsetZ);   // "c12/p3/l1", смещение от места

public sealed record UsePlan(string Id, string Kind,
    double OffsetX, double OffsetY, double OffsetZ);   // "c12/p3/u0"
```

Точный набор полей уточняется при реализации; **неизменны** три вещи:
план — чистые данные без Godot, он детерминирован, и id иерархические.

### 3. Детерминизм и id

- ГПСЧ куска: `Pcg32(Hash(worldSeed, chunkIndex))`.
- ГПСЧ места: `Pcg32(Hash(worldSeed, chunkIndex, placeIndex))`.
  Состав места (лут, точки) берётся **только** из его ГПСЧ. Поэтому новый тип
  дома в одном месте не сдвигает ничего у соседей.
- `Hash` — свой (например, SplitMix64 по сиду и индексам), не `GetHashCode()`:
  тот меняется между запусками .NET.
- Разные решения одного места (тип, положение, лут) берут **разные потоки**
  PCG: `new Pcg32(Hash.Mix(seed, кусок, место), sequence: поток)`. Не сдвигать
  номер места (`место + 3`): так ГПСЧ одного места совпадает с ГПСЧ другого.
  Решения уровня куска — «место» −1.
- Форма дороги зависит от сида (амплитуды и длины волн), а не только от фазы.
  Тест `RoadActuallyTurns` не даёт ей выродиться в прямую.
- Id: `c{кусок}/p{место}`, `c{кусок}/p{место}/l{лут}`, `…/u{точка}`.
  В `WorldState` хранятся как `loot:c12/p3/l1`, `gate:c4/p0` и т. д.

### 4. Опасность растёт с расстоянием

`Tier(s)` — одна функция в ядре, всё остальное читает её: таблицы лута,
звери, шанс поломки, выбросы. Пример: тир 0 — до 1 км, затем +1 каждые 3 км,
максимум 10. Конкретные числа — баланс, их правят в одном месте.

### 5. Сцена: подгрузка кусков (фаза 2)

- `ChunkStreamer` (Node) держит загруженными куски `[k−1, k+3]` вокруг игрока
  (по станции машины или пешехода, кто дальше от загруженного края).
- Кусок строится по `ChunkPlan`: полоса дороги, террейн, обочины, места, лут.
  Выгрузка — `QueueFree` корня куска. Состояние (лут, шлагбаумы) в
  `WorldState`, поэтому при повторной загрузке кусок такой же.
- Постройка куска не должна давать рывок: бюджет ≤ 4 мс на кадр, остальное —
  в следующих кадрах (очередь).
- **Плавающее начало координат.** Godot считает в `float`: после ~10 км
  дрожат физика и камера. Когда игрок уходит дальше 2 км от начала, весь мир
  сдвигается обратно, а сдвиг копится в `OriginS`. Ядро считает в `double`
  и о сдвиге не знает.

### 6. Сейв

- Позиция машины хранится в координатах мира в `double` (`s`, `lateral`, высота,
  yaw), а не в координатах сцены — они меняются при сдвиге начала.
- `WorldState` — как есть, с новыми id.
- **Правила для версий сейва** (действуют для всех изменений `SaveData`):
  1. Новая версия читает предыдущую: отсутствующие поля получают значения
     по умолчанию, переименованное поле читается под старым именем.
  2. На каждую версию — файл-образец `core/Krntija.Core.Tests/Saves/save_vN.json`
     и тест «образец vN загружается без исключений и без потерь».
  3. До первой публичной сборки допускается **ломающий** переход, если он
     записан в ADR. Переход v2 → v3 ломающий для `WorldState`: старые id
     (`loot:poi:3`) в новом мире не существуют и отбрасываются; игрок, машина,
     инвентарь и деньги переносятся.

## Фазы

**Фаза 1 — ядро (модель фич).** `RoadCurve`, `WorldGenerator`, `ChunkPlan`,
`Tier`, `Hash`. Только `core` и тесты, сцену не трогать. Тесты минимум:

- один сид и кусок → одинаковый план (дважды и в разном порядке вызовов);
- `Plan(seed, 7)` не зависит от того, строили ли до этого 0…6;
- id уникальны в куске и между кусками; формат id;
- ограничения дороги (п. 1) на 100 км;
- места не стоят на дороге и не пересекаются друг с другом;
- `Tier` не убывает с расстоянием;
- кусок 0 содержит дом игрока; первые куски дают заправку и блокпост
  (как сейчас: игрок сразу встречает экономику и шлагбаум).

**Фаза 2 — сцена (архитектор).** `ChunkStreamer`, плавающее начало,
постройка куска по плану, перенос `RoadMeshBuilder`/`TerrainBuilder` на куски,
сейв v3, `--perf` на 10 км пути.

**Фаза 3 — наполнение (модель фич).** Перенос содержимого `RoadsideMap`,
`BackcountryMap`, `MapLife` в планировщик (ядро решает «что и где», сцена
строит геометрию). Удаление тупика «Конец» и задачи «доехать до последней
точки». Регионы по `Tier`.

До конца фазы 3 **не делать** фич, завязанных на фиксированную длину дороги
или на конкретный индекс точки центральной линии.

## Уточнения после фазы 1 (2026-10-25)

Ответы на вопросы модели фич; действуют как часть контракта.

1. `RoadCurve` — экземпляр по сиду (`WorldGenerator.Curve(seed)`), не статика. Принято.
2. `PlacePlan.OnRoad` — флаг, а не отдельный тип: на полотне может стоять
   разное (блокпост, позже завал, брошенная машина). Принято.
3. Слоты `48 + 80·i ± 6 м`, ≤ 3 мест в куске — временно. В фазе 3 их заменяет
   `Footprint` (см. п. 6).
4. Второй заход лута при `Tier ≥ 3` — принято, числа — баланс.
5. Отрицательный кусок — исключение. Стример не спрашивает −1 (кусок ≥ 0). Принято.
6. **`Footprint` добавить** в `PlacePlan` первым шагом фазы 3: полуширина и
   полуглубина в осях места (или радиус). Сцена по нему выравнивает площадку
   земли (вместо `WorldArtGround`) и расчищает растительность; ядро — проверяет
   непересечение мест геометрией, а не слотами.
7. `RoadCurve.Project(x, z)` — обратная к `Offset` (добавлена в фазе 2): по
   точке мира даёт станцию и смещение. Её использует земля и автопилот.

## Контракт фазы 2 для фазы 3

- **Кто владеет корнем куска.** `ChunkStreamer` создаёт узел `Chunk_{k}` под
  `Chunks` и удаляет его целиком при выгрузке. Всё содержимое куска — дети
  этого корня, в его локальных координатах (якорь — ось дороги в начале куска).
  Ничего из куска не добавлять в `Main` напрямую: иначе при выгрузке и сдвиге
  начала координат оно останется висеть.
- **Как строится.** `ChunkBuilder.BuildStep(step, root, …)` — шаги по
  ≤ 4 мс. Места строятся отдельным шагом через `PlaceBuilder` (фаза 2б):
  по `PlaceKind` выбирается строитель геометрии, он получает `PlacePlan` и
  корень места; точки взаимодействия и лут он не регистрирует сам, а
  возвращает описания с id из плана, их регистрирует `Main`.
- **Id в `WorldState`.** Лут — `loot:{LootPlan.Id}` (`loot:c12/p3/l1`), точки
  с состоянием — `{вид}:{UsePlan.Id}` (`gate:c2/p0/u0`), место —
  `place:{PlacePlan.Id}` (награда за первое посещение).
- **Возврат в кусок.** Кусок всегда пересобирается по плану, затем на него
  накладывается `WorldState`: подобранный лут не ставится, оплаченный
  шлагбаум открыт. Сцене как источнику состояния не доверяем.
- **Проверки.** `--chunk-bench` (шаг постройки), `--chunk-run` (10 км, без
  дыр в дороге, без утечки узлов, с переносом начала, без ссылок на выгруженные
  куски) и `--chunk-places` (места из плана; лут и шлагбаум после выгрузки и
  возврата) — в `check.ps1`.
- **Как сделано в 2б** (`game/scripts/PlaceBuilder.cs`). Шаг 3 из 7 строит все
  места куска. `PlaceBuilder.Build` ставит узел `Place_c{k}_p{i}` в центр места
  (`Offset(S, Lateral)`, поворот `−Yaw`, высота — `ChunkBuilder.Ground`) и
  возвращает `Built`: точки (`Use`) и лут (`Loot`) в координатах корня куска.
  `ChunkStreamer.ChunkReady` → `Main.OnChunkReady` регистрирует их с номером
  куска, `ChunkUnloading` снимает. Точки плана ставятся на землю по смещению в
  осях места; если в модели есть узел `{Вид}Anchor` (`PumpAnchor`,
  `SleepAnchor`), берётся он.
- **Что фазе 3 учесть.**
  - Дом игрока (`House`, `c0/p0`) строит `PlayerHouse` со своими дверями,
    сундуком, верстаком и кроватью; точки `door/chest/bed` из плана для него
    не используются. Либо убрать их из плана, либо подогнать под планировку.
  - У `Abandoned` пока нет интерьера: его `door/chest/bed` не регистрируются
    (`chest` в игре — это склад дома, а не ящик с лутом). Нужен свой вид точки.
  - Награда за посещение — только заметные места (`WorldActions.RewardsVisit`:
    заправка, село, блокпост, руины, ферма). Сараи и колодцы стоят в каждом
    куске — награда за них раздула бы экономику.
  - `StaticBatcher.Merge` — только для построек из ящиков (сейчас дом): обход
    GLB-модели стоит до 8 мс и ничего не сливает (текстуры).
  - Модели мест грузятся заранее (`PlaceBuilder.Preload`): первая загрузка GLB
    посреди поездки — рывок 20–35 мс. Новую модель места добавить в `ModelIds`.
  - Деревья и трава не растут в круге `PlaceBuilder.ClearRadius` — временно,
    до `Footprint`.

## Ход фазы 2

- **2а (готово):** дорога, земля сеткой по мировым координатам (нет складок
  на крутых поворотах, нет швов между кусками), горы, деревья, трава,
  километровые столбы, невидимые стены по краям полосы, плавающее начало
  координат с глобальным параметром шейдеров `world_origin`, автопилот по
  кривой. Включается флагом `--world=chunks`; старый мир по умолчанию.
  Замеры (GTX 1060, окно, без VSync): 10 км со скоростью 480 м/с — 2,2 мс на
  кадр в среднем; шаг постройки — в среднем ≤ 3 мс, пик ~5 мс.
- **2б (готово):** места, лут и точки взаимодействия из плана (дом игрока,
  заправка, блокпост со шлагбаумом, колодцы; модели GLB или заглушки),
  `WorldState` по id плана, награда за первое посещение, миникарта по
  построенному отрезку кривой. Шаг «места» — в среднем 0,4 мс, пик 1,7 мс
  (дом и блокпост строятся в стартовых кусках вне бюджета). Старт игры —
  станция 8 м: дом (s = 24) впереди слева.
- **2в:** сейв v3 (позиция в координатах мира), мир кусками по умолчанию,
  старый — под `--world=legacy` до конца фазы 3.

## Последствия

- Сцена теряет право решать, что где стоит: генераторы в `game/scripts`
  станут «строителями по плану».
- Кооп получает одинаковый мир по сиду без передачи карты.
- Старые сейвы теряют состояние мира (см. п. 6.3).

## Пересмотреть, если

- понадобится дорога с развилками и выбором маршрута (тогда `s` → граф);
- постройка куска не уложится в бюджет кадра даже с очередью.
