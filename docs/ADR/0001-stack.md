# ADR 0001 — Godot 4 + C#-ядро, отдельно от движка

- **Дата:** 2026-10-23
- **Статус:** принято

## Контекст

Нужен движок и архитектура для игры, которую делает один человек вместе с
AI-агентом. Ключевые ограничения:

- агент должен уметь читать и править сцены, а не только скрипты;
- нужен кооп 2–4 по Steam-инвайтам без своего бэкенда;
- нужен автоматический прогон тестов без GUI;
- железо: GTX 1060 6 GB, 8 потоков.

## Решение

1. **Godot 4.7 (.NET)** как движок.
2. **Симуляция — в `core/`, чистая C#-библиотека** без ссылок на Godot.
3. **Сцены собираются кодом** там, где это возможно (машина, тестовый полигон),
   `.tscn` — только для композиции верхнего уровня.
4. **net8.0** для `core/` — совместимо и с .NET 8, и с более новыми рантаймами.

## Почему Godot, а не Unity

| Критерий | Godot | Unity |
|---|---|---|
| Сцены как текст | да (`.tscn`) | YAML с GUID, агенту тяжело |
| Стоимость | 0 | 0 до $200k, но лицензионная возня |
| Сборка из CLI | одна команда | лицензия в CI |
| Готовые ассеты машин | мало | много |
| Кооп по Steam | GodotSteam + SteamMultiplayerPeer | Steamworks.NET, зрелее |
| Вес билда | десятки МБ | сотни МБ |

Решающим был первый пункт: скорость совместной работы человека и агента важнее
готовых ассетов. Машину и окружение всё равно делаем свои — лоу-поли.

## Почему ядро отдельно

Физику твёрдого тела считает движок, но все *системы* (износ, топливо, голод,
экономика, сейвы) — чистые функции состояния. Это даёт:

- тесты без движка (быстро, детерминированно);
- сервер = тот же код с другим транспортом;
- баланс правится в одном месте.

## Последствия

- Придётся самим настроить подвеску и руль (2–3 дня на feel).
- Консолей не будет.
- Зато экспорт, CI и мультиплеер — дёшево.

## Пересмотреть, если

- понадобятся консоли или Steam Workshop в первые 6 месяцев;
- физика машины упрётся в возможности движка.
